# Technical Documentation: `Text-Grab/Models/ResultTable.cs`

## Overview

The `ResultTable.cs` file defines data structures and table reconstruction algorithms used in **Text-Grab**. Its primary purpose is to process word-level or line-level Optical Character Recognition (OCR) bounding boxes (`WordBorderInfo`), organize them into tabular rows and columns using spatial clustering techniques, and serialize the formatted table structure into plain text (e.g., TSV/tab-delimited output) or WPF UI overlays.

The file contains four main classes:
1. `ResultTable`: Core manager and engine for detecting, clustering, and formatting OCR bounding boxes into grid-like tables.
2. `ResultColumn`: Model representing a single column's spatial horizontal boundaries and identifier.
3. `ResultRow`: Model representing a single row's spatial vertical boundaries and identifier.
4. `ResultTableCell`: Model representing a cell position (Row ID, Column ID) and text content.

---

## Architecture & Data Models

### 1. `ResultColumn`
Represents the calculated horizontal extent of a column in the table.
* **`Width`** (`double`): Total width of the column ($Right - Left$).
* **`Left`** (`double`): The minimum X-coordinate (left edge) of the column.
* **`Right`** (`double`): The maximum X-coordinate (right edge) of the column.
* **`ID`** (`int`): Sequential index identifier for the column.

### 2. `ResultRow`
Represents the calculated vertical extent of a row in the table.
* **`Height`** (`double`): Total height of the row ($Bottom - Top$).
* **`Top`** (`double`): The minimum Y-coordinate (top edge) of the row.
* **`Bottom`** (`double`): The maximum Y-coordinate (bottom edge) of the row.
* **`ID`** (`int`): Sequential index identifier for the row.

### 3. `ResultTableCell`
A lightweight representation of tabular cell contents.
* **`ResultRowID`** (`int`): Row index.
* **`ResultColumnID`** (`int`): Column index.
* **`ResultText`** (`string`): Text content residing in the cell.

### 4. `ResultTable` Properties
* **`Columns`** (`List<ResultColumn>`): Active columns generated by table analysis.
* **`Rows`** (`List<ResultRow>`): Active rows generated by table analysis.
* **`OcrResult`** (`OcrResult?`): Backing OCR result instance (optional).
* **`BoundingRect`** (`Rect`): Enclosing bounding rectangle encompassing the full table with padding.
* **`ColumnLines`** (`List<double>`): X-coordinates representing split lines between automatic and manual columns.
* **`RowLines`** (`List<double>`): Y-coordinates representing split lines between automatic and manual rows.
* **`ManualColumnSeparators`** (`List<double>`): User-added or manually defined column separator positions.
* **`ManualRowSeparators`** (`List<double>`): User-added or manually defined row separator positions.
* **`TableLines`** (`Canvas?`): A WPF `Canvas` containing drawn borders and visual lines representing table boundaries.

## Core Operations & Logic

### 1. Table Analysis Pipeline (`AnalyzeAsTable`)

The primary logic for reconstructing tables is driven by `AnalyzeAsTable(...)`.

#### Workflow:
1. **Sanitization**: Standardizes and trims the text of input `WordBorderInfo` tokens.
2. **Threshold Calculation**:
   * Measures the median height of non-zero bounding boxes. Defaults to `20` if `NaN` or $\le 0$. The row center threshold is set to $\max(4, \text{medianHeight} \times 0.75)$.
   * Measures the median width of non-zero bounding boxes. Defaults to `40` if `NaN` or $\le 0$. The column center threshold is set to $\max(24, \text{medianWidth} \times 0.9)$.
3. **Spatial Clustering**:
   * Calls `BuildRowsByCenterClustering` to group tokens into rows based on vertical center-line proximity and perform cleanup/merges.
   * Calls `BuildColumnsByCenterClustering` to group tokens into columns based on horizontal center-line proximity and perform cleanup/merges.
4. **Line Calculation**: Invokes `ParseRowAndColumnLines()` to derive midpoints between adjacent rows and columns to establish `RowLines` and `ColumnLines`.
5. **Manual Separators**: Merges and sanitizes user-provided manual row and column separators (`ApplyManualSeparators`).
6. **Grid Assignment**: Maps each `WordBorderInfo` object to its calculated `ResultRowID` and `ResultColumnID` based on center points relative to line separators via `AssignWordBordersToFinalGrid`.
7. **Drawing Overlay (Optional)**: Generates visual table lines on a WPF Canvas using `DrawTable()` if `drawTable` is true.

---

### 2. Clustering Algorithms

#### Row Clustering (`BuildRowsByCenterClustering`)
* Words are ordered primarily by vertical center point ($Top + \frac{Height}{2}$) and secondarily by Left coordinate.
* Iterates through sorted words, aggregating tokens into existing Y-axis clusters if the distance between the word's center Y and the cluster's center Y is within `centerThreshold`.
* **Post-Processing Merges**: Two merging sweeps combine single-word outlier rows with neighboring clusters if the gap between their centers is within `mergeThreshold` ($\max(\text{centerThreshold} \times 1.5, \text{medianHeight})$).

#### Column Clustering (`BuildColumnsByCenterClustering`)
* Words are ordered primarily by horizontal center point ($Left + \frac{Width}{2}$) and secondarily by Top coordinate.
* Aggregates tokens into X-axis clusters if the distance between centers falls within `centerThreshold`.
* **Post-Processing Merges**: Merges adjacent clusters if a cluster contains $\le 1$ word and its width is less than $40\%$ of the average cluster width, or if the gap between adjacent clusters is smaller than $\max(6, \text{centerThreshold} \times 0.25)$.

---

### 3. Parsing and Utility Methods

* **`ParseOcrResultIntoWordBorderInfos`**: Converts an `IOcrLinesWords` OCR result structure into a list of normalized `WordBorderInfo` instances mapped to physical DPI scales.
* **`ParseOcrResultWordsIntoRects`**: Converts internal `OcrResult` line/word bounds into standard WPF `Rect` structures.
* **`ParseRowAndColumnLines`**: Computes `BoundingRect` (with padding) enclosing all rows/columns and fills `ColumnLines` and `RowLines` with midpoints between consecutive column bounds and row bounds.
* **`SanitizeManualSeparators` & `MergeSeparatorLines`**: Cleans up manually provided line split coordinates, ensures minimum separation gaps using `GrabFrameTableEditState.TryNormalizeSeparatorPosition`, removes duplicate positions, and merges automatic and manual line coordinate arrays.
* **`CountSeparatorsBefore`**: Helper that takes line coordinates and calculates how many separator boundaries precede a given spatial coordinate (used to derive Row and Column IDs).
* **`Median`**: Utility method calculating the median from a collection of `double` values (ignoring `NaN` and `Infinity`).
* **`MergeTheseRowIDs`**: Merges outlier rows into adjacent rows by expanding the nearest neighbor row's vertical bounds to eliminate sparse row fragmentation.

---

### 4. Text Generation (`GetTextFromTabledWordBorders`)

Generates structured tabular text output (typically tab-delimited string format) from processed `WordBorderInfo` lists.

#### Formatting Strategy & Rules:
1. **Sorting**: Sorts words by `ResultRowID`, then `ResultColumnID`, and resolves ties using vertical placement (`Top`) when horizontal distance between elements falls within a tie threshold of $12\text{px}$.
2. **Tab Insertion**: Tracks column jumps (`ResultColumnID` shifts). Appends horizontal tabs (`\t`) for each column transition when processing multi-row tables.
3. **Percent Sign (%) Normalization**:
   * Integrates heuristic rules to attach standalone or trailing `%` signs directly to preceding numbers within short visual tolerances (e.g., merging separate `%` tokens or `"1%"` OCR artifacts directly to preceding numerical digits).
   * Identifies percent-dominant columns. If a column consistently contains percentage values, plain numbers in that column are automatically formatted with a trailing `%` sign if missing.
   * Checks for footnote tokens (e.g., `(1)`) via `IsFootnoteToken` to prevent invalid percent merging on annotated rows.
4. **Spacing Logic**: Ensures spaces are inserted between adjacent words within the same cell while omitting invalid spaces near tabs or newline characters.
5. **Text Normalization**: Replaces HTML/XML encoded characters like `&` (`\u0026`) with standard character representations.

---

## WPF Canvas Visualization (`DrawTable`)

When UI rendering is requested, `DrawTable()` constructs a WPF `Canvas` containing visuals of the table structure:
* **Outer Outline**: A 3px border drawn using system color `RGB(40, 118, 126)` corresponding to `BoundingRect`.
* **Vertical Lines**: 2px wide vertical `Border` elements positioned at each coordinate in `ColumnLines`.
* **Horizontal Lines**: 2px high horizontal `Border` elements positioned at each coordinate in `RowLines`.
